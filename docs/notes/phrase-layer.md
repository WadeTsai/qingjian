# 短語層（2026-09-12）

## 起因

常數掃描（`constant-sweep.md`）之後看沒命中的構成：詞級 1208 條沒命中裡 742 條是 5 鍵以上的短語當詞選，
日誌裡上屏過、詞庫沒有的漢字串 2271 個，選過兩次以上的 449 個，最常見的是 我的（57 次）/ 好的 / 都是 / 更好 / 我覺得 / 而不是。
它們不是「新詞」，是常用詞表（liuxilu 5.6 萬條）按詞典收詞原則不收的組合；`mine` 挖語料那步的虛詞規則又把含 的 / 不 / 是 / 有 的全濾掉了。
所以缺的不是資料新舊，是「人會整塊打出來」的短語層。

## 挖法：`dict-convert phrases`

- 語料按詞庫分詞，兩遍掃：第一遍數相鄰兩詞，第二遍數兩段二元都夠頻的相鄰三詞。
- 次數按語料檔案分開數，**總次數與對話語料（LCCC）裡的次數都要 ≥ 2000**：維基裡的模板句（一個市鎮、面積為、人口密度）次數再高也不是人會打的。
- 不用點互資訊：虛詞組合的 PMI 天然低，而它們正是要收的。只用邊界規則（`phrases/rules.rs`）：
  不以 的了著得地嗎吧呢啊 開頭，不以 不沒很太也都又再才還把被和與及或而且但 與數詞結尾；代詞 + 了 / 這 / 那 是碎片；
  單字 + 代詞只認 給讓幫等找叫送陪問那… 這些（給我 / 那我 成，這你 / 天你 不成）；次數剛過線的再套「單字 + 的 只認代詞」「是 / 在 + 單字不要」，
  夠常見的（≥ 5 倍下限）不套——好的 / 真的 / 是啥 是人天天打的，多的 / 歲的 / 是新 不是。
- 笑聲串不算相鄰：你哈哈哈 切成 你 / 哈哈 / 哈，一個 哈 token 挨著另一個 哈 時含它的視窗不計，否則 你 + 哈哈 會灌成高頻短語。
  孤立的 哈 照常，所以 你哈（謝謝你哈，LCCC 三千多次）仍在——它是真的。
- 讀音由成分詞拼出（同一個詞多個讀音取詞頻最高的），不用再標多音字；`--extra-words` 檔案加了第三列拼音，`lexicon` 給了就不按字猜。
- 結果 5398 條（二詞 4300 多、三詞 1100 左右），人工抽樣精度約九成，覆蓋日誌 449 個缺詞裡的 188 個（語料裡 ≥ 20 次的 299 個裡 170 個）。
  剩下的是 詞庫 / 對齊 / 後端 這類語料裡少的領域詞，與 是不 / 看一 這類日誌裡接受的碎片。
- 詞庫已併入短語後重跑要 `--refresh assets/lexicon/phrases.tsv`：不摘掉上次的短語，我的 就是一個詞，挖不出 我 + 的（踩過：只挖出 34 條）。

## 進語言模型的三種接法（都在同一份凍結日誌 + 整句評測集上比）

| 接法 | 整句評測集首選 | 回放 詞 | 回放 整句 |
|---|---|---|---|
| 改前 | 37.6% | 8032 | 3045 |
| A 短語當 token 重訓 bigram | 38.4% | 8092 | 2878 |
| B 語言模型不動、短語只進詞庫 | 37.6% | 8067 | 2929 |
| C 分詞摘掉短語、統計完按成分合成計數（採用） | 37.6% | 8064 | 2978 |

A 的整句評測漲了 0.8 個點（短語 token 相當於給了三元上下文），但回放掉 5 個點，看明細兩個機制：
① 二十 壓過 而是——短語當 token 後語料裡的「而是」都歸了 token，「而 + 是」的二元證據沒了，而是 的一元又比 二十 低；
② 不對 / 不在 / 等會 / 放到 這類整句恰好是一個詞的，以前是 Viterbi 路徑 不 + 對 當整句候選排最前，現在整段是一個詞就不出整句候選，
按詞級排序放，部隊 這種維基高頻詞壓上來。B 沒有①，但②仍在：短語對語言模型是未知詞，兜底扣 4 nat。

C 是 `bigram --phrases`：分詞時把短語摘掉（二元證據保住），統計完給每條短語合成
一元 = c(a,b)、前接 c(v,短語) = c(v,a)·c(a,b)/c(a)、後接 c(短語,w) = c(a,b)·c(b,w)/c(b)，
於是 P(短語|v) = P(a|v)·P(b|a)、P(w|短語) = P(w|b)，短語在詞圖與詞級排序裡的得分與原來走兩個詞的路徑一樣，只是多了個能整塊選的詞。
合成行 186 萬條另加、不佔真實二元行的 300 萬名額（佔了會把低頻真實行擠掉，整句評測掉 0.4）；`lm.qj` 29 MB → 44 MB，載入仍在 100 ms 內。

## C 的回放整句 −67 是什麼

新增沒命中 75 條、修好 30 條。75 條裡：

- 一半以上是尺子偏差：舊引擎沒有 那就是 / 你可以 / 我現在 / 然後就是 這些短語，使用者當時只能選字首 那就 / 你可 / 我先 再接著打，
  日誌記的是字首；現在短語排第一、字首第二，反而對。沃德 壓 我的 也是回放早期從日誌學了 沃德。
- 十來條真翻轉：猜對 / 才對、不聽 / 不停、沒法 / 沒發、說道 / 說到、要得 / 要的、在哪 / 在那、回事 / 會是。
  這是聊天語料的先驗與這個使用者的習慣不一致，兩邊都是合法短語；個人學習選一次就翻回來。
- 比較好 / 比較高（`bijiaogao`）：短語的一元是它真實的出現機率，比原來兩步路徑的乘積略高（差約 1 nat），剛好讓鄰鍵糾錯 g → h 贏了。
  整句評測集裡沒有敲錯，所以那把尺子看不到這一類；量小，先不管。

## 品牌詞

`assets/lexicon/brand.tsv`：青簡 210，既是詞頻也寫進語言模型一元（句首二元按八分之一算，與 請柬 的句首佔比一致）。
只寫詞頻沒用：詞級排序用語言模型機率，語料裡沒有的詞兜底扣 4 nat，青簡 排不進前三；句首二元給整個 210 又壓過了整句 請見。
目標是 `qingjian` 下 請見（整句）/ 青簡 / 請柬 的順序，使用者選一次個人學習就把它頂到第一。

## 復現

```bash
cargo run --release -p qingjian-dict-convert -- phrases data/corpus/*.txt          # 重跑加 --refresh assets/lexicon/phrases.tsv
cp data/generated/phrases.tsv assets/lexicon/phrases.tsv
cargo run --release -p qingjian-dict-convert -- lexicon --pinyin data/generated/pinyin-llm.jsonl --frequency data/generated/lm-unigram.tsv \
  --extra-words assets/lexicon/mined_words.tsv --extra-words assets/lexicon/phrases.tsv --extra-words assets/lexicon/brand.tsv
cargo run --release -p qingjian-dict-convert -- bigram --phrases assets/lexicon/phrases.tsv --phrases assets/lexicon/domain_words.tsv --brand assets/lexicon/brand.tsv data/corpus/*.txt
```

再 `pack dict` / `pack lm`（`bundle.sh` 會做），然後 `--eval-text data/eval/sentences.tsv` 與 `--replay` 凍結日誌各跑一遍與改前比。
