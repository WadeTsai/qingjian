# 輔碼

issue #8：聯想裡沒有的詞要翻很多頁；加輔碼（拼音後補碼篩選）能把第一次打句子的效率提上來，選過一次的詞靠既有學習在下次純拼音就往前排。
本文是這份需求的設計來源：**要做什麼、為什麼這麼做、資料從哪來、許可怎麼算**。實現按 `docs/plan/todo.md` 排期。

## 術語

| 詞 | 意思 |
|---|---|
| 輔碼 | 拼音之後鍵入的、用來縮小候選範圍的碼。形態是「拼音 + 觸發鍵 + 碼」。 |
| 觸發鍵 | 進入輔碼態的那個鍵。可配置，預設 `;`。 |
| 碼段 | 輸入串裡觸發鍵之後的字母，與拼音段分開記賬、分開畫。 |
| 碼錶 | 「詞 → 碼」的對映資料，匯入與管理的單位。 |
| 原生表 | 隨包分發、開箱可用的碼錶。v1 只有筆畫。 |
| 引導匯入 | 不隨包帶表，由使用者自己從官方渠道取得碼錶後一鍵匯入。第三方形碼（小鶴形、自然碼形）走這條路。 |

## 輔碼的語義（Core）

### 觸發

- 配置項 `[general] aux_code_key`，預設 `;`；也想跟霧凇（反引號 + 偏旁部首拼音）或永珍（`/` 前置引導符）對齊的使用者改這一個鍵即可。
- **優先順序規則（與現有行為共存）**：當前 preedit 能完整切分成音節、且敲下的字元是配置的觸發鍵 → 進輔碼態；否則維持現有語義（`;` 仍按中文標點轉全形、不會轉全形的符號仍進英文直輸段——會轉全形的標點先把高亮候選上屏再補標點——翻頁鍵仍是翻頁鍵）。
- 微軟 / 搜狗雙拼裡 `;` 是 `ing` 的韻母鍵：**能構成合法音節就當韻母，否則當觸發鍵**。`x;` 是 xing（`;` 被韻母吃掉），再敲一個 `;` 才進輔碼態。

### 過濾

- **詞級（含單字）**：碼只篩詞候選，不改選詞邏輯，也不改整句轉換。
- **逐鍵即篩**：碼段每多一個字母就重新篩一次，不要求敲滿該詞的碼位；敲到滿意即可上屏。
- **無碼詞在輔碼態直接隱藏**：碼錶沒覆蓋的詞不出候選；碼段刪空後**停在輔碼態**——`;` 仍在、候選全部回來，空碼段再按一次退格才退出（`[general] aux_code_keep_empty`，預設開；關掉則刪空即回純拼音態）。
- **篩空時候選視窗收起**，只剩拼音行。

### 學習（issue 裡「下一次不用輔碼也能聯想出來」就落在這）

不新造機制：輔碼態選中的詞按**輸入串**記進 `user-choices.tsv`（詞級排序裡同輸入串選過的優先），並計入詞頻與個人 n-gram。
下次同樣的拼音，這個詞自然往前排。也就是說輔碼只需解決「第一次怎麼少翻頁」。

### 與整句、簡拼的關係

v1 只支援**全拼 + 輔碼**、**雙拼 + 輔碼**。簡拼 + 輔碼、整句轉換 + 輔碼（形碼逐字約束進 Viterbi 詞圖）都留到後續，見「後續與不做」。

## 碼錶

### 格式：Rime `.dict.yaml`

沿用已有的 Rime 詞庫匯入傳統（`crates/qingjian-dictionary/src/import/rime.rs` 已能把 `.dict.yaml` 轉成 `.qj`），碼錶用它同一套外形：

- 頭部 `---` … `...` 是 meta（`name` / `version` / `sort`），正文每行 `詞\t碼[\t權重]`，`#` 是註釋。
- `columns` **必須解析**：預設是 `text` / `code` / `weight` 三列，但真實存在 `columns: [text, weight]` 的純詞表——照預設解析會把詞頻當碼，靜默寫壞資料。解析按 `columns` 列表的下標定位。
- `import_tables` 表示**跨檔案合表**（一本碼錶由 base + stem + extended 拼成）：匯入時一併讀入，否則資料不完整。
- 「有詞無碼」的行**要報錯或警告**，不能像詞庫匯入那樣靜默跳過（碼錶少一行就是少一個詞可用，使用者得知道）。
- 匯入完成給一份統計：讀入多少條、多少詞有碼、多少詞無碼、跳過多少行。

### 索引：獨立碼索引，兩段式查詢

碼錶**不能複用詞庫的儲存**：

- 詞庫的 `Slot{text_start, frequency, text_len, reserved}` 沒有碼欄位；
- 鍵空間會串臺——`de` / `he` / `bu` / `ge` 這類兩位碼同時是合法拼音音節，同一個索引裡既當碼又當拼音，約束互相汙染。

所以碼錶落成**自己的索引**（碼 → 詞集合），查詢是兩段式：先用拼音段查詞庫得到候選集合，再用碼段在該索引裡取交集、按碼命中重排。碼錶檔案與詞庫檔案一樣進使用者資料目錄，單獨管理。

### 原生表：只帶筆畫

第三方形碼錶都不隨包，理由在「許可」一節。隨包的只有筆畫：

- **鍵位**：`h` 橫、`s` 豎、`p` 撇、`n` 捺（含點）、`z` 折——與大陸廠商（搜狗 / QQ）的筆畫輸入一致，鍵盤手位在拼音區。
- **取碼**：單字「前 4 筆 + 末筆」；片語每字首筆（二字 2 碼、三字 3 碼、四字以上 = 前三字首筆 + 末字首筆）。
- **歸一化**：點與捺合併為 `n`、提併入橫。
- **資料管線**：以 **CNS11643 全字型檔「筆順資料」**（`CNS_strokes_sequence.txt`，官方定義 1 橫 / 2 豎 / 3 撇 / 4 點 / 5 折）作字形來源，經官方 CNS→Unicode 對照表對映；其上疊加**大陸序覆蓋表**——CNS 是台灣標準，與大陸規範按部件成片不一致（艹：臺 4 筆首筆豎 / 陸 3 筆首筆橫；辶 4/3、阝 3/2），一級字抽樣 299 字裡 31 例筆畫數不符（10.4%）。**混合表不可接受**：rime-stroke 就是雙軌（花 = 艹 4 畫台灣序、節 = 艹 3 畫大陸序），大陸使用者按學校筆順敲不出 花 這類字。
- **工具**：`tools/dict-convert` 新增 `stroke` 子命令，輸入 `--cns-seq`（筆順表）、`--cns-map`（CNS→Unicode 對照）、`--cns-count`（可選，與筆畫數自洽過濾，建議 `|d| ≤ 1`）、`--filter`（字表白名單，取通用規範字表）、`--prc-rules`（大陸序覆蓋），輸出 `字\t[1-5]{n}`（8,105 字約 40–80 KB）。原始 zip 不入庫，走 `data/` 的既有慣例只留生成產物。

### 匯入

- **「匯入碼錶…」**：接受 Rime `.dict.yaml`，走系統開啟檔案對話方塊 / 檔案選擇器；失敗時在視窗底部紅字一行說明（例如「這個檔案裡沒有識別到碼錶（需要詞 + 碼兩列）」）。
- 匯入完成給一份統計：讀入多少條、多少詞有碼、多少詞無碼、跳過多少行。
- 引導匯入的文案要寫清：碼錶由使用者自己取得（例如小鶴形的官方碼錶），青簡不隨包分發第三方形碼錶。

### 設定介面（兩個殼都要做）

同一組設定項在兩個平臺的設定介面各出現一次，寫進同一份 `config.toml`（配置檔案是唯一事實源）：

| 設定項 | macOS（偏好設定，AppKit） | Windows（設定程式，WinUI 3） |
|---|---|---|
| 觸發鍵 | 錄製按鈕，預設 `;` | 錄製控制元件，同一預設 |
| 候選上顯示碼 | 勾選框，預設不勾 | 同左 |
| 碼錶列表 | 隨包筆畫標「隨包」不可移除；匯入的顯示名字 · 條數 · 許可，可開關、可移除（與「詞庫」頁同構） | 同結構的一頁 |
| 匯入碼錶… | 系統開啟檔案對話方塊 | 系統檔案選擇器 |

設定項命名、文案與失敗提示兩平臺保持一致；Core 只提供配置項與狀態，介面歸殼。

## 候選視窗與輸入串

- **輸入串（preedit）**：碼段用**淡色 + 下劃線**畫法、`;` 不突出——與既有段樣式同一套視覺詞彙（敲的拼音正常色、剩餘拼音畫淡、被糾錯改掉的畫刪除線）。Core 把碼段作為新的段型別（`MarkedKind`）給出，兩個殼各自落到自己的載體：macOS 走行內 marked text 與視窗拼音行，Windows 走 `protocol` 的 `PreeditSegment`（TSF DLL 交給系統）。
- **候選**：輔碼態只出命中碼的詞（無碼詞隱藏）；敲碼篩空時候選視窗收起，只剩拼音行。
- **顯示碼開關開啟時**：碼用方括號**緊跟在候選詞後面**（`1 鶴[rbm] crane`，渲染器 `Row.code`，小字淡色）：碼是詞本身的屬性，不進右側的 annotation；譯文仍是候選詞的單條 annotation（`docs/design/architecture.md`）。開著時不用進輔碼態：純拼音打字與輔碼態空碼段也把詞的**首條碼**掛上（邊打邊認碼），篩碼時顯示命中的那條。豎排會比純譯文擠、橫排更難放下，這是這個開關的已知代價（預設關）。
- 窗口布局、視覺層級、翻頁鍵等沿用 `docs/design/candidate-ui.md`；**繪製歸各殼**（macOS 自繪 NSPanel，Windows Server 自繪候選窗與狀態條）。渲染器 spike（`crates/qingjian-render`，分支 `renderer-spike`）落地後兩個平臺都只貼圖。

## 配置

| 鍵 | 預設 | 說明 |
|---|---|---|
| `[general] aux_code_key` | `";"` | 觸發鍵，可改反引號或 `/` |
| `[general] aux_code_show` | `false` | 候選上是否顯示碼（與譯文拼接；開著時未進輔碼態也顯示詞的首條碼） |
| `[general] aux_code_keep_empty` | `true` | 碼段刪空後是否留在輔碼態（空碼段再按一次退格才退出）；`false` 刪空即回拼音態 |
| `[aux_code] enabled` | `false` | 輔碼總開關：關掉整條輔碼線（`;` 回到原生行為）；開著但沒有可用碼錶也不進輔碼態 |
| `[aux_code] disabled` | `[]` | 關掉某張匯入的碼錶，與 `[dictionaries] disabled` 同形 |

## 分層與落點

| 層 | 放什麼 |
|---|---|
| `qingjian-core` | 碼段解析（觸發鍵消歧、碼段與拼音段分開記賬）、碼索引的兩段式查詢、過濾與重排、`MarkedKind` 新段；碼錶查詢走 trait，不認識檔案 |
| `qingjian-dictionary` | 碼錶解析（`.dict.yaml` + `columns` / `import_tables` 規則）、獨立碼索引與落盤、匯入統計 |
| `qingjian-platform` | 配置項、碼錶與方案的目錄與開關 |
| 平臺殼 | macOS：`apps/macos`（IMK 偏好設定頁、候選窗自繪）；Windows：`apps/windows/settings`（WinUI 3 設定頁）與 `apps/windows/server`（自繪候選窗與狀態條）。兩邊都只做兩件事：把碼段畫出來、把設定介面畫出來 |

平臺層不出現排序邏輯、詞庫訪問或翻譯呼叫（`docs/design/architecture.md` 的架構約束）。

## 測試與評測

- **Core 單測**：碼段解析與消歧（`x;` = xing、再 `;` 才進輔碼）、逐鍵即篩、無碼詞隱藏、碼段刪空兩態（預設停在輔碼態、`aux_code_keep_empty = false` 回拼音態）、碼錶 `columns` / `import_tables` / 「有詞無碼」三類邊界。
- **學習閉環**：輔碼態選詞後，同輸入串（純拼音）首選命中——用 `apps/cli --replay` 在現有輸入日誌上驗。
- **評測**：匯入時報告「多少詞有碼 / 無碼」，用碼錶覆蓋率與 `--eval-text` 的整句命中率當兩把尺子。
- 排序、整句、糾錯的改動一律先跑 `--replay` 與 `--eval-text`（倉庫既有規矩）。
- **Windows**：本機只 `cargo check --target x86_64-pc-windows-gnu`；真編譯與真機測試在 Windows 機器上做（Server + TSF DLL + 設定程式）。
- **macOS**：IMK 不能 `cargo run` 驗證，要 `apps/macos/scripts/bundle.sh --install` 裝到本機；`osascript` 往 TextEdit 發按鍵讀迴文本可做端到端。

## 許可

- 專案是 **GPL-3.0-or-later**（`LICENSE`、`Cargo.toml`）。
- **小鶴形**（小鶴音形的形碼部分）：官網宣告「未經本站允許，不得用於任何商業目的」+ All Rights Reserved，**無開放許可**，不能隨包；要內建須先取得作者書面許可。
- **自然碼形**：作者堅持商業發行，形碼無授權記錄，不能隨包。
- **筆畫（CNS11643 筆順資料）**：台灣數位發展部開放資料，許可為「政府資料開放授權條款第 1 版」或「OFL-1.1」二選一，可再分發、含商用，**需署名**——隨包時在「關於」頁與資料目錄署名，沿用 `assets/levels`、`assets/glossary` 的做法。
- **Make Me a Hanzi / hanzi-writer-data**：PRC 筆順，只作開發期差異定位，**不隨包**（其筆順資料是 Arphic Public License）。
- **第三方碼錶不隨包**：碼錶由使用者自己從官方渠道取得後匯入；這是工程偏好（檔案小、可控、不帶上游維護負擔），不是許可禁令。
- 使用者匯入第三方碼錶是使用者自己的行為，不構成再分發。

## 後續與不做

**平臺範圍**：本設計對兩個現役平臺一視同仁——macOS（`apps/macos`）與 Windows（`apps/windows/{server,tsf,settings}`）的殼與設定介面都要接；邏輯全在 Core，Linux 未開工，落地時走同一套通路，不需要改 Core。

**落地分工**（按 `docs/contributing.md`「一個 PR 只做一件事、只碰一個平臺」）：三步可以獨立合，只有一個平臺機器的人也能完成自己那一步——

| 步 | 範圍 | 驗證方式 |
|---|---|---|
| 1 | **Core**：碼錶解析、獨立碼索引、碼段與兩段式查詢（單獨一個 PR，不碰殼） | `cargo test -p qingjian-core` / `-p qingjian-dictionary`、`apps/cli` 手測、`--replay` |
| 2 | **Windows 殼**：Server / TSF 的 preedit 分段與候選繪製、`apps/windows/settings`（WinUI 3）的「輔碼」頁 | Windows 機器上 `cargo check --target x86_64-pc-windows-gnu` + 真機部署（Server + DLL + 設定程式） |
| 3 | **macOS 殼**：IMK 的 marked text 分段、候選窗繪製、偏好設定頁 | macOS 機器上 `bundle.sh --install` + 真機輸入驗證 |

第 1 步是後兩步共同的前置；**第 2、3 步之間沒有依賴**——先合哪一個都行，只有一個平臺的貢獻者只做自己那一步，另一平臺由別的貢獻者或維護者補。

**後續（未定，需要時另開設計）**：簡拼 + 輔碼；整句轉換 + 輔碼（形碼逐字約束進詞圖）；碼錶匯入後的生效時機與熱切換。

**不做**：五筆原生表；社群碼錶線上下載 / 同步；內建任何第三方形碼錶。
